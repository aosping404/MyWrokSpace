# GitHub Actions CI/CD 工具 - 快速使用指南

## 真正使用时需要配置什么？

### 第一步：准备环境

#### 方法 1：使用 Conda（推荐）

```bash
# 1. 创建 conda 环境（如果还没有）
conda env create -f environment.yml

# 2. 激活环境
conda activate github-actions-ci-tool

# 3. 运行工具
python create_github_actions_ci.py
```

#### 方法 2：使用系统 Python

```bash
# 1. 安装依赖
pip install -r github_actions_tool_requirements.txt

# 2. 运行工具
python create_github_actions_ci.py
```

### 第二步：使用工具配置

打开工具后，**只需要配置以下必填项**：

#### ✅ 必填配置

1. **项目名称**（必填）
   - 例如：`my_qt_project`
   - 用于生成配置文件中的项目名称

2. **选择平台**（至少选一个）
   - ☑ Windows (windows-latest)
   - ☑ macOS (macos-latest)
   - ☑ Ubuntu (ubuntu-latest)

#### ⚙️ 可选配置（有默认值，可以不改）

- **Qt 版本**：默认 `6.8.3`，可选择其他版本
- **Python 版本**：默认 `3.10`
- **构建类型**：默认 `Release`，可选 `Debug`
- **触发条件**：默认开启 `push` 和 `pull_request`
- **上传构建产物**：默认开启

### 第三步：生成配置文件

1. **预览配置**：点击"预览配置"查看生成的 YAML 内容
2. **生成文件**：点击"生成配置文件"保存到 `.github/workflows/ci.yml`

### 第四步：提交到 Git 仓库

```bash
# 1. 进入您的 Qt 项目目录
cd /path/to/your/qt/project

# 2. 复制生成的配置文件到项目
cp -r .github/ /path/to/your/qt/project/

# 3. 提交到 Git
git add .github/workflows/ci.yml
git commit -m "添加 GitHub Actions CI/CD 配置"
git push
```

### 第五步：在 GitHub 上查看

1. 进入您的 GitHub 仓库
2. 点击 "Actions" 标签页
3. 查看构建状态和结果
4. 下载构建产物（如果启用）

## 最小配置示例

**最快使用方式**：

1. 填写项目名称：`my_project`
2. 保持默认设置（三个平台都选中）
3. 点击"生成配置文件"
4. 完成！

## 常见问题

### Q: 必须安装 Conda 吗？

A: **不一定**。可以选择：
- 使用 Conda（推荐，隔离环境）
- 使用 pip + 系统 Python
- 使用 venv 虚拟环境

### Q: 需要配置 GitHub 仓库吗？

A: **不需要额外配置**。生成的配置文件会自动使用：
- `actions/checkout@v4` - 拉取代码
- `jurplel/install-qt-action@v4` - 安装 Qt（自动配置）
- `actions/setup-python@v4` - 配置 Python
- `jwlawson/actions-setup-cmake@v1.14` - 配置 CMake

### Q: 我的项目不是 CMake 项目怎么办？

A: 生成的配置默认使用 CMake。如果您的项目使用 qmake，需要手动修改生成的 `ci.yml` 文件中的构建步骤。

### Q: 构建失败怎么办？

A: 检查以下几点：
1. 项目根目录是否有 `CMakeLists.txt`
2. Qt 版本是否与项目兼容
3. GitHub Actions 日志中的错误信息

### Q: 需要设置 GitHub Secrets 吗？

A: **通常不需要**。此工具生成的配置使用公开可用的 Actions，不需要额外的密钥。

## 配置文件位置

生成的配置文件路径：
```
.github/workflows/ci.yml
```

**重要**：确保将这个目录提交到 Git 仓库，GitHub Actions 才能正常工作。

```
1. 运行工具 → 2. 填写项目名称 → 3. 生成配置 → 4. 提交到 Git → 5. 推送到 GitHub → 6. 自动构建
```

就这么简单！
